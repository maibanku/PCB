# 22-05 测试策略

> 所属 [[22-工程化与非功能]]。针对几何运算、规则引擎、格式适配器、命令栈等关键模块建立分层测试体系（单元/集成/回归/端到端），保障核心引擎确定性。

## 目标（要实现什么）
- 单元测试覆盖核心模块：几何布尔运算/偏移、DRC 规则、命令栈事务、序列化、约束求解
- 格式适配器回归测试：每个支持的格式（KiCad/Altium/Eagle/ODB++/IPC-2581/Gerber）有"导入→导出→比对"金标准用例
- 确定性测试：相同输入产出字节级一致输出（无头导出、AI 建议的种子化测试）
- 集成测试：端到端"建库→画图→DRC→导出→下单"关键路径自动化
- 性能回归：与 [[22-工程化与非功能/01-性能基准]] 协同，性能不退化作为 gate
- 测试数据管理：公开测试工程集 + 合成工程生成器，避免商业工程依赖

## 关键点
- 测试金字塔：单元为主、集成适度、端到端少量关键路径
- 格式适配器是回归重灾区：每次格式升级须跑全量金标准，附迁移报告对比
- AI 相关测试用种子化 + mock 模型，避免依赖云端不可复现
- 覆盖率目标：核心模块 ≥90%，业务模块 ≥70%，作为 PR gate 而非建议
- Fuzz 测试：几何运算/格式解析纳入 fuzz，捕获边界崩溃

## 输入 / 输出
- **入**：核心模块代码、格式适配器、测试工程集、覆盖率目标
- **出**：测试报告（单元/集成/回归）、覆盖率统计、性能回归报告、缺陷追踪
