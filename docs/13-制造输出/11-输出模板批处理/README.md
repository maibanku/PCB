# 13-11 输出模板批处理

> 所属 [[13-制造输出]]。定义输出作业（Output Job）模板：列出本次要导出的全部文件（Gerber/Excellon/PnP/BOM/PDF/IPC-2581...），一键批量执行，避免逐项手工导出。

## 目标（要实现什么）
- 输出作业（.outjob）文件：列出所有输出项（output cell），每项定义类型、配置、目标路径
- 支持的输出类型：Gerber / Excellon / PnP / 钢网 / BOM / IPC-2581 / ODB++ / PDF（装配/制造） / DXF / STEP
- 一键执行：单次操作生成所有列出的输出文件，含进度条与失败重试
- 输出路径模板：可配置目录结构（如 `output/{project}/{version}/gerber/`、`/bom/`、`/pdf/`）
- 文件命名模板：占位符 `{project}`、`{version}`、`{layer}`、`{date}`、`{variant}`
- 模板复用：保存为工程模板，新工程可加载（如"嘉立创打样模板"、"Multek 量产模板"）
- 版本管理：每次执行记录版本号 + 时间戳，输出文件夹按版本归档（如 `v1.2.3_20260727/`）
- CLI 命令行支持：`eda-cli export --outjob my.outjob`，CI/CD 集成（F4 工具链）
- 失败处理：单项失败不阻塞其他输出，最终汇总报告（成功/失败/警告）
- 与 [[13-制造输出/12-制造前检查]] 联动：批处理前自动跑一次 DFM 前置检查

## 关键点
- Output Job 是企业研发的核心提效工具：避免漏导出（导致工厂缺文件退单）
- 模板化让"同一工厂多项目"配置一致，减少错误
- CLI 与 CI/CD 是企业差异化：每次 git tag 自动生成全量生产包，归档到 release
- 文件夹结构有讲究：分离 gerber/bom/pdf/3d 等子目录，工厂接收清晰
- 版本号必须严格（语义化版本 + git commit hash），避免错用旧版本输出
- 与 [[13-制造输出/12-制造前检查]] 联动：跑通 DFM 前置后再批量输出，杜绝"输出完才发现不可造"
- Altium 的 OutputJob、KiCad 的 plot 计划是参考

## 输入 / 输出
- **入**：PCB 工程、输出作业模板（.outjob）、版本号
- **出**：完整生产包（多文件夹 + 文件）、执行报告、归档文件夹

## 依赖
- **上游**：所有其他 13-* 子功能（作为输出项）
- **下游**：工厂交付、CI/CD（F4）、设计归档
