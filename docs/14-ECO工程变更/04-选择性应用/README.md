# 14-04 选择性应用

> 所属 [[14-ECO工程变更]]。按需勾选并应用 ECO 列表中的变更项：支持逐项接受/拒绝、批量选择、依赖检查与预览，避免"全有或全无"的粗暴同步。

## 目标（要实现什么）
- 用户在 ECO 列表中勾选/取消勾选每一项，支持单选、Shift 范围选、Ctrl 多选
- 按规则批量选择：如"接受所有 Add 类"、"拒绝所有 Rename"、"接受所有 Footprint 变更"
- 应用前强制预览（[[05-变更预览与日志]]）：显示选中 ECO 的累积影响
- 依赖检查：若选中 ECO 依赖未选 ECO（如选中"删除网络 X"但未选"删除 X 上的器件"），警告或自动加选
- 应用顺序：按依赖拓扑排序（Add → Modify → Rename → Remove），保证一致性
- 部分应用：只应用选中项，未选项保留为 Pending 状态，下次同步可继续
- 错误恢复：单项应用失败时，回滚该项但不影响其他项（事务化）
- 与命令栈（B3）联动：每次应用生成一个 Undo 节点（可整体撤销整批 ECO）

## 关键点
- 选择性应用是"显式可审查"ECO 的关键（相比 KiCad 的全同步机制）
- 依赖关系：很多 ECO 不能孤立应用（如"修改 R1 封装"必须有 R1 存在）
- 事务化：每项 ECO 应用是原子操作，失败不应污染数据
- 应用顺序：拓扑排序避免"先删除依赖项"
- 部分应用是工作流：用户可能"今天先应用封装变更，下周再处理网络重命名"
- 与命令栈合并：选中多项 ECO 一次应用可合并为单一命令（"Apply 5 ECOs"），Undo 一次撤销全部

## 输入 / 输出
- **入**：ECO 列表（[[03-ECO列表]]）、用户选择
- **出**：应用后的设计数据、应用报告（成功/失败/跳过）
