# 14-06 回滚与审计

> 所属 [[14-ECO工程变更]]。支持已应用 ECO 的回滚（基于命令栈）与完整审计追踪（谁/何时/改了什么/为什么），满足企业研发与功能安全合规要求。

## 目标（要实现什么）
- **回滚（Rollback）**：
  - 基于 B3 命令栈，单次 ECO 应用对应一个 Undo 节点
  - 批量 Undo：选中多个 ECO 节点一次性回滚（保持依赖顺序倒序）
  - 时间点回滚：选择历史某时刻的设计状态（基于版本快照）
  - 回滚也产生审计日志（" reverted ECO-005 at 2026-07-27 14:30"）
- **审计追踪（Audit Trail）**：
  - 完整记录：用户、时间、操作类型、对象、Before/After、来源（手动/ECO/导入）
  - 不可篡改：日志写入工程文件后追加写，不允许编辑历史
  - 数字签名（可选）：企业版支持变更签名（PKI）
- **版本快照（Snapshot）**：
  - 关键节点自动快照（每次应用 ECO 后、每次保存时）
  - 用户手动打 tag（如 "v1.2.3 - sent to factory"）
  - 快照可对比、可回滚
- **审计报告**：按时间段、用户、对象类型生成审计报告（PDF/CSV），供 ISO 审查
- **变更溯源**：选中当前任意元素（器件/网络）→ 显示其完整变更历史
- 与 F1 Git 集成：变更可作为 Git commit，享受 Git 的版本管理能力

## 关键点
- 命令栈（B3）是回滚的技术基础：每个 ECO 是一个命令栈条目，Undo 天然支持
- 审计日志的"不可篡改"是企业/功能安全要求（IEC 61508 / ISO 26262 / DO-254）
- 数字签名：高可靠场景（航空/医疗/汽车）需要变更签名，防止抵赖
- 版本快照存储成本：每次快照可能数十 MB，需差分存储（git-like 对象数据库）
- 与 F1 Git 集成：自有格式 + Git 后端 = 双重保险（本地快照 + 远程 Git）
- 审计报告模板：按行业预设（医疗 FDA 21 CFR Part 11、汽车 IATF 16949）

## 输入 / 输出
- **入**：已应用的 ECO 历史、命令栈、用户身份
- **出**：回滚后的设计状态、审计日志、审计报告、版本快照对比
