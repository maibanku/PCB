# 05-02 开放文本格式

> 所属 [[05-工程与文件系统]]。设计自有**开放文本格式**：描述性数据用 TOML/JSON（Git diff 友好），二进制资源（3D/图片）单独存引用，使整个工程可在 Git 中版本化、可 diff、可 merge。

## 目标（要实现什么）
- **格式选型**：TOML 为主（人读/写友好，注释支持），JSON 为辅（程序间交换）；schema 版本化（`schema_version = 1`）
- **核心文件类型**：
  - `project.toml`：工程根（树结构、元数据、依赖库版本锁定）
  - `*.sch.toml`：原理图页（器件实例、导线、网络标号、层次块）
  - `*.pcb.toml`：PCB 版图（板框、器件、走线、铺铜、叠层、规则）
  - `*.sym.toml` / `*.fp.toml` / `*.dev.toml`：符号/封装/器件库单元（与 C1 协作）
  - `*.lib.toml`：库清单与版本
  - `*.rule.toml`：约束规则集
  - `*.layout.toml`：UI 布局状态（可选）
- **二进制资源引用**：3D STEP、位图、字体用 `ref = "res://models/X.step"` 引用，单独存储（不混入文本）
- **路径方案**：`res://`（工程内）、`user://`（用户级）、`lib://`（库引用）三类前缀，借鉴 Godot Resource 路径
- **Schema 向后兼容**：版本号 + 迁移器（旧工程自动升级，不丢数据）
- **diff 友好**：稳定字段顺序、避免行内嵌套过深、列表按 id 排序，使 `git diff` 输出可读
- **校验工具**：CLI 提供 `eda validate project.toml`，CI/CD 前置检查
- **人类可编辑**：高级用户可直接编辑文本（如批量改位号、调线宽），编辑器下次加载生效

## 关键点
- **Git 友好是核心**：相对 KiCad（XML 啰嗦）和嘉立创（自有闭源），本品格式更紧凑可读
- **schema 稳定**：破坏性变更走主版本号，迁移器自动升级，用户无感
- **资源引用而非内嵌**：避免文本文件膨胀，3D 模型单独存
- **不锁定**：开放规范，社区可写工具（与 F3 格式兼容协作，提供互转）

## 输入 / 输出
- **入**：内存中的数据模型（节点树/Resource）
- **出**：可序列化的文本文件 + 二进制资源清单

## 依赖
- **上游**：`core/io/Resource`（序列化基类）、`third_party/rapidjson` 或 `toml++`
- **下游**：[[01-工程树]]（project.toml）、[[03-版本快照]]（基于文本格式做 diff）、所有编辑器（读写图页文件）、Git 集成（F1 协作）
