# 05-03 版本快照

> 所属 [[05-工程与文件系统]]。实现本地版本历史与文件恢复（轻量时间机器）：定时 + 手动保存工程快照，可对比/回滚到任意历史点，与 Git 互补（Git 是文件级，快照是工程级"另存为"）。

## 目标（要实现什么）
- **自动快照**：定时（默认 10 分钟）+ 关键操作前（运行 DRC/导出 Gerber/大改 ECO）自动存档
- **手动快照**：菜单"保存快照..."，支持命名 + 备注（如"布局完成，待评审"）
- **快照存储**：增量 diff（基于 [[02-开放文本格式]] 的文本格式）+ 引用去重，节省磁盘
- **快照列表 UI**：时间线视图，显示快照时间、备注、缩略图、变更摘要
- **对比视图**：选中两个快照，图形化 diff（如原理图差异高亮、PCB 走线变更）
- **回滚**：一键恢复到任意快照（保留当前为"恢复前"快照，避免误操作丢数据）
- **快照上限**：本地保留 N 个（默认 100），超出按策略清理（保留关键节点 + 时间衰减）
- **与 Git 互补**：快照是工程级"项目状态"，Git 是文件级版本控制；快照可一键 commit 到 Git
- **分支（可选）**：从快照分叉试验性修改，不影响主线（轻量"分支"概念）

## 关键点
- **基于文本格式增量**：快照不复制全量，只存 diff，磁盘占用可控
- **关键节点自动触发**：DRC/导出前的快照避免"改坏找不回"
- **与 Git 不冲突**：Git 是协作/长期归档，快照是个人短期实验，分工明确
- **图形化 diff 是核心**：文本 diff 看 PCB 难，图形化（原理图叠加、PCB 走线高亮）才有用

## 输入 / 输出
- **入**：当前工程状态、定时器/用户触发
- **出**：快照记录（diff + 元数据）、可恢复的历史点

## 依赖
- **上游**：[[02-开放文本格式]]（增量 diff 基础）、[[01-工程树]]（工程状态）
- **下游**：所有编辑器（提供"对比/回滚"入口）、用户（恢复历史）
