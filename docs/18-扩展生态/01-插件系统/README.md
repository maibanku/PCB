# 18-01 插件系统

> 所属 [[18-扩展生态]]。借鉴 Godot `GDExtension` 思路，提供原生 C++ 插件的加载、版本协商、沙箱隔离与细粒度权限管控，作为第三方扩展 EDA 能力的统一底座。

## 目标（要实现什么）
- 提供稳定的 ABI/版本协商机制（参考 GDExtension），允许插件跨主版本加载，加载失败时给出明确降级或拒绝策略
- 支持插件注册自定义图元、规则、面板、菜单、命令、文件格式适配器等扩展点（类 Godot `register_types`）
- 实现沙箱化执行：限制插件可访问的文件路径、网络、子进程、剪贴板等敏感能力；崩溃隔离不影响主进程
- 提供细粒度权限声明清单（manifest），用户安装时可见所申请权限并可逐一授权/撤销
- 支持热加载/卸载（开发期）与签名校验/来源校验（生产期），未签名插件默认禁用并告警
- 内置一套最小官方插件（如默认主题包、立创商城比价、IPC-7351 封装向导）用于验证扩展点完备性

## 关键点
- 沙箱优先借鉴进程级隔离 + 显式 IPC（而非同进程裸指针），防止第三方代码污染核心引擎确定性
- 扩展点须与核心引擎解耦：通过接口/注册表暴露，不允许插件直接修改核心数据结构
- 权限模型需对齐 [[22-工程化与非功能/04-安全]] 的总体安全策略
- 沙箱内渲染/GPU 资源须通过受控句柄传递，避免插件越权读取工程内存

## 输入 / 输出
- **入**：插件包（含二进制、manifest、签名）、用户授权决策、主程序扩展点注册表
- **出**：注册到 UI/规则/格式系统的扩展能力、加载与权限审计日志、沙箱运行时状态
