# EDA 自研软件 · 知识库总索引

> 纯 C++20 自研引擎（借鉴 Godot 架构）的竞品级全栈 EDA 套件知识库。**差异化**：AI 辅助设计 + 供应链集成。**灵魂主线**：端到端"画图 → 验证 → 输出可直接生产文件"闭环。

## 编号体系

- **顶层目录 = Plan**：`01`~`22` 对应 22 个 Plan（**编号即 Plan 号**）；`00-总览` 放跨模块纲领；`参考/` 放对照研究。
- **域内子目录 = 子功能**：每个域下 `MM-中文名` 编号该域的具体业务/功能。
- 每个目录都有 `README.md`（定位 / 子功能 / 依赖 / 状态）。

## 文档约定（frontmatter schema）

所有 Markdown 文件使用统一 YAML frontmatter，字段顺序与取值如下：

| 字段 | 必填 | 取值 / 说明 |
|------|------|------|
| `title` | 是 | 文档标题（可含编号前缀，如 `08 PCB编辑器`） |
| `lang` | 是 | 语言代码；当前全库 `zh-CN`。i18n 平台（Crowdin/Weblate）识别字段 |
| `status` | 是 | `待实现` \| `设计中` \| `实现中` \| `已实现` \| `权威` |
| `parent` | 子功能必填 | 父域，如 `08-PCB编辑器` |
| `plan` | 域/子功能必填 | Plan 号，如 `P8` / `P8a` |
| `phase` | 域 README 必填 | 如 `Phase 2 · MVP 闭环` |
| `priority` | 域 README 必填 | `MVP` \| `二期` \| `差异化` \| `贯穿` |
| `tags` | 是 | inline `[EDA, Pxx, ...]` 或多行 list（纲领文档） |
| `related` | 推荐 | wiki 链接数组，指向强关联文档 |
| `created` | 纲领推荐 | 创建日期 |

**状态机**：`待实现`（默认，子功能/域）→ `设计中`（正在 writing-plans）→ `实现中`（已开工）→ `已实现`。`权威` 用于不随 Plan 状态变化的稳定文档（三纲领、术语表、参考、已定稿设计笔记）。

**术语**：写文档/代码/翻译前先查 [[00-总览/04-术语表]]——元件/器件、courtyard、Via/Pad、品牌名等四层命名映射（英文 source / 代码符号 / 中文术语 / 文件名）以此为准。

## MVP 边界

Phase 0+1+2 = **P1–P8、P11、P13、P14**（跑通"画图 → 输出可生产文件"最小闭环）；F3 仅 KiCad 导入子集。

**关键路径**：P1 → P2 → P3/P4（并行）→ P5 → P6 → P7 → P8 → P11 → P13 → P14。

## 工作流（进入某 Plan 时）

1. 查 [[00-总览/03-项目目录结构]] 确认代码目录位置
2. 读对应域 `NN-域名/README.md` + 子功能占位
3. `brainstorming` 细化设计 → `writing-plans` 产出 `plan/` 实现计划
4. TDD 落码（对齐 Godot 目录、CMake、头源同目录、`eda::` 命名空间）
