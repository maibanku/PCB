# 16-05 元件库格式

> 所属 [[16-格式兼容]]。各 EDA 厂商符号库 / 封装库 / 3D 库的互转与归一化。**二期实现**（MVP 仅 KiCad 库子集）。

## 目标（要实现什么）
- 各 EDA 厂商符号库 / 封装库 / 3D 库互转：覆盖 KiCad (`.kicad_sym` / `.pretty`)、Altium (`.SchLib` / `.PcbLib` / `.IntLib`)、Eagle (`.lbr`)、OrCAD (`.OLB`)、PADS (`.lib`)、立创 JSON 库主流格式
- 器件一体化适配：源格式可能是分离（如 KiCad 符号库 + 封装库独立）或一体（如 Altium `.IntLib`），目标统一为内部"一体化器件 = 符号 + 封装 + 3D + 参数 + 供应链"模型（[[06-元件库]]）
- Pin 映射重建：符号 Pin 与封装 Pad 的对应关系（Pin Map）从源格式提取；缺失时提供交互式重建工具
- 3D 模型迁移：STEP / wrl 关联与单位/原点/旋转校准，确保 [[10-3D与机械协同]] 装配检查有效
- 批量库转换：目录级批量转换（一个库目录 → 一组内部器件），转换日志含每件状态（成功/部分/失败）与原因
- 库版本锁定：导入的库写入工程依赖（[[05-工程与文件系统]]），绑定版本与来源元数据，避免再次迁移后结果不一致

## 关键点
- 各厂商库语义差异大：KiCad 符号 Pin 与封装 Pad 通过 `Footprint Library` 名字引用，Altium `.IntLib` 是编译后二进制
- Pin Map 缺失是常见痛点：Altium `.SchLib` 与 `.PcbLib` 是分离的，对应关系靠 `Designator` + `Pin Number`，需校验
- 3D 关联：Altium 用 `3D Body` 嵌入或外链，KiCad 用 `(model "...")` 引用 `.wrl/.step`，路径与单位（inch/mm）需标准化
- 批量转换性能：万级器件库需流式解析 + 多线程，避免一次性载入内存
- 与 [[06-元件库]] 的"库版本管理 + 依赖锁定"机制深度集成，确保可复现

## 输入 / 输出
- **入**：各 EDA 库文件（KiCad/Altium/Eagle/OrCAD/PADS/立创）
- **出**：内部一体化器件库（[[06-元件库]] 模型）+ Pin Map + 3D 关联 + 转换日志
