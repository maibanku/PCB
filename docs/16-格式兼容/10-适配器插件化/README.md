# 16-10 适配器插件化

> 所属 [[16-格式兼容]]。定义统一的格式适配器接口，支持插件化扩展新格式，社区可贡献。**二期实现**。

## 目标（要实现什么）
- 统一适配器接口：定义 `IFormatImporter` / `IFormatExporter` 抽象基类（C++20 接口，纯虚函数），统一 Import/Export 流程与错误处理
- 适配器注册机制：适配器自注册（static initializer 或 manifest），主程序启动枚举可用格式与能力声明
- 插件动态加载（二期）：基于 [[18-扩展生态]] 模块系统（GDExtension 思路），第三方格式适配器作为 `.so` / `.dll` / `.dylib` 动态加载，沙箱隔离
- 能力声明：每个适配器声明支持能力（导入/导出、工程/库/原理图/PCB、版本范围、文件扩展名），供 UI 与 [[16-格式兼容/08-迁移向导]] 迁移向导筛选
- 适配器测试框架：标准测试用例库（公开格式的样本文件 + 期望输出），社区贡献适配器需通过测试方可上架
- 文档与示例：适配器开发指南（API/数据模型/错误处理/保真度报告接口），含最小可运行模板，便于社区贡献新格式

## 关键点
- 接口设计：`detect(path) -> bool` / `import(path, ctx) -> Project` / `export(project, path) -> void` + 进度回调 + 错误聚合
- 内置适配器（KiCad/Altium/Eagle 等）与第三方适配器共享同一接口，确保一致性
- 沙箱化：第三方适配器进程隔离或受限权限（借鉴 [[18-扩展生态]] 沙箱），防止恶意/有 bug 的适配器崩溃主程序
- 注册机制：基于 manifest JSON（`format_adapter.json` 声明能力）+ 运行时反射（[[02-核心对象体系]] ClassDB）
- 与 [[18-扩展生态]] 的插件市场集成，社区适配器可作为独立扩展分发

## 输入 / 输出
- **入**：适配器实现（内置或第三方）+ manifest 声明 + 测试用例
- **出**：统一导入/导出能力 + 适配器注册表 + 适配器开发 SDK 与文档

## 依赖
- **上游**：[[02-核心对象体系]]（ClassDB 反射）
- **可选/二期**：[[18-扩展生态]]（插件动态加载与沙箱，二期软依赖，核心适配器接口不依赖）
- **下游**：[[16-格式兼容/01-KiCad格式]]~[[16-格式兼容/07-ODB与IPC与Gerber反向解析]]（内置适配器遵循本接口）、[[16-格式兼容/08-迁移向导]]（迁移向导枚举适配器）
