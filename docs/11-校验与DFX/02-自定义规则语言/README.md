# 11-02 自定义规则语言

> 所属 [[11-校验与DFX]]。提供类约束表达式 + 脚本的自定义规则语言，让用户/企业扩展 ERC/DRC/DFX 规则，对标 KiCad DRC 规则脚本但更强。

## 目标（要实现什么）
- **声明式表达式**：规则结构 = `query(对象集) → condition(布尔/数值谓词) → message(违例描述) + severity`。
- 内置查询域：nets / pads / tracks / components / vias / layers / regions，支持属性链（`net.length`、`pad.spacing(other)`、`component.height`）。
- 表达式运算：算术/逻辑/集合（含 `forall`/`exists`/`count`/`sum`），类 KiCad DRC 语法但更通用。
- **脚本扩展**：复杂规则嵌入 Python（CPython）或自研轻量脚本（类 GDScript 思路），可访问工程对象模型。
- 规则调试：dry-run + 命中高亮（在 PCB/原理图标注匹配对象），降低编写门槛。
- 规则版本化、入工程、可分享/云同步（与 11-05 规则集预设联动）。
- AI 辅助：自然语言 → 自动生成规则草稿（"USB 差分对阻抗 90Ω" → 规则文本），可接受/拒绝（E1）。

## 关键点
- **DSL vs 脚本分层**：表达式 DSL 覆盖 90% 常见规则（安全、快），脚本兜底复杂逻辑（如基于网络拓扑的检查）。
- **性能护栏**：脚本规则限时/限量（避免用户写出 O(n²) 拖死全板校验），可标注"slow rule"。
- **安全**：脚本沙箱（限制文件/网络访问），与 F2 插件沙箱策略一致。

## 输入 / 输出
- **入**：用户编写的规则文本（DSL/脚本）、工程对象模型（nets/pads/...）。
- **出**：编译后的规则实例（注入 11-01 引擎）、调试命中可视化、规则错误诊断。

## 依赖
- **上游**：P2（对象模型 API）、P3（几何 API）。（F2 脚本沙箱、E1 AI 规则生成为可选后置增强：MVP 期 DSL 自带安全子集、不依赖 F2 沙箱；F2=P18、E1=P20 属 Phase 4/5，而 P11 属 Phase 2 MVP。）
- **下游**：11-01（规则执行）、11-05（规则集打包/分享）。
