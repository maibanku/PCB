# 06-08 版本管理与依赖锁定

> 所属 [[06-元件库]]。实现库单元的版本化 + 工程对库版本的"依赖锁定"：库单元（符号/封装/器件）带版本号，工程引用时锁定具体版本，保证"今天能造的板，三年后打开还能 100% 复现"。

## 目标（要实现什么）
- **库单元版本化**：每个符号/封装/器件带 `version`（语义化 `MAJOR.MINOR.PATCH`）+ `checksum`（内容哈希）
- **变更规则**：
  - PATCH：修 bug（如修正引脚名拼写），向后兼容
  - MINOR：增属性（如加新参数），向后兼容
  - MAJOR：破坏性（改引脚号映射、改焊盘尺寸），需工程显式升级
- **工程依赖锁定**（`project.toml` 中的 `[[libs.deps]]`）：记录所依赖库的 uuid + version + checksum，工程打开时校验 checksum，不一致时告警（避免库被静默修改）
- **锁文件**（`project.lock.toml`）：精确记录所有依赖的具体版本 + checksum（类似 Cargo.lock / package-lock.json），保证可复现
- **升级流程**：检测可用更新 → 显示变更 diff → 用户确认升级 → 更新锁文件
- **回滚**：升级后出问题可回退到锁文件的历史版本
- **库冻结快照**：工程打包归档（[[05-工程与文件系统/06-工程打包归档]]）时把所依赖的库单元快照进归档（离线 100% 复现）
- **企业库的版本策略**：发布版本（稳定）/ 草稿版本（内部测试），工程可指定通道

## 关键点
- **可复现是工业级硬需求**：KiCad 库更新后老工程可能跑偏；本品锁定保证确定性问题（与"AI 不破坏工程确定性"呼应）
- **语义化版本**：MAJOR/MINOR/PATCH 明确变更影响，用户决定何时升级
- **锁文件是真相**：`project.lock.toml` 记录精确版本，团队共享保证一致
- **与打包归档协作**：归档即冻结快照，工厂移交 100% 可造（不因库更新漂移）

## 输入 / 输出
- **入**：库单元的版本/校验和、工程的依赖声明
- **出**：锁文件（精确版本快照）、版本校验/升级提示
