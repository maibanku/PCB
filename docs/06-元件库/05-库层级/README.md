# 06-05 库层级

> 所属 [[06-元件库]]。实现多级库层级体系：本地库 / 在线云端库 / 企业私有库三层结构，支持库同步、权限控制与冲突合并，覆盖个人创客到企业团队的需求。

## 目标（要实现什么）
- **多级库结构**：
  1. **本地库**（`user://libs/`）：用户私有，随用户跨工程共享
  2. **工程库**（`<project>/libs/`）：工程自包含，随包带走（与 [[05-工程与文件系统/06-工程打包归档]] 联动）
  3. **在线云端库**（HTTPS 同步）：官方维护 + 社区共享，定期同步本地缓存
  4. **企业私有库**（HTTPS/SSH/S3）：企业内部统一库源，支持鉴权与权限
- **搜索优先级**：工程库 > 本地库 > 企业库 > 云端库（就近解析，避免云依赖）
- **库元数据**：每库带 `name`、`uuid`、`version`、`source`、`sync_policy`、`last_synced`
- **同步策略**：
  - 手动同步（按钮触发）
  - 自动同步（启动时 / 定时）
  - 离线模式（仅本地缓存，不联网）
- **冲突处理**：同名库单元冲突时，按优先级取上层；提供"覆盖/保留两者/合并"选项
- **权限控制**（企业库）：读/写/管理员三级，写入需鉴权（与 F5 安全协作）
- **库索引缓存**：本地维护索引（名称/参数/标签），搜索不联网
- **库订阅**：用户可订阅第三方库（如某厂商官方库），自动同步更新

## 关键点
- **多级覆盖**：工程自包含优先，避免"同事的工程打开缺库"
- **企业场景必备**：私有库 + 权限，是企业版差异化（vs KiCad 无库管理）
- **离线可用**：云端库本地缓存，断网仍能用
- **官方云端库**：作为差异化（KiCad 无官方云库，靠社区），官方维护标准器件库

## 输入 / 输出
- **入**：各库源（本地/HTTP/SSH）、用户同步操作
- **出**：统一的库查询接口（按优先级解析），供 [[07-库搜索]] 和编辑器使用

## 依赖
- **上游**：`platform/Network`（HTTP/SSH 同步）、`core/io/Resource`
- **下游**：[[07-库搜索]]、[[08-版本管理与依赖锁定]]（库版本）、所有编辑器（器件放置时解析库）
