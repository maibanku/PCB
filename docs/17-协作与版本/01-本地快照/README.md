# 17-01 本地快照

> 所属 [[17-协作与版本]]。设计过程中的本地版本快照保存与回溯，先于 Git 提供更轻量的版本保护。

## 目标（要实现什么）
- 自动快照：基于编辑器空闲时段或操作阈值（每 N 步命令栈操作 / M 分钟空闲）自动保存工程快照到本地 `.snapshots/` 目录
- 手动快照：用户主动命名快照（如"提交前"、"布局完成"、"改板前"），含描述、时间戳、作者元数据
- 快照时间线：编辑器内可视化时间线，浏览历史快照，预览差异（与当前对比，复用 [[17-03]] 图形化 diff）
- 一键恢复：选中快照恢复到任意历史版本，恢复前自动保存当前为"恢复前"快照，避免数据丢失
- 快照存储：基于工程文本格式（JSON/TOML，[[05-工程与文件系统]]）+ 二进制资源，去重（内容寻址）与压缩，避免历史膨胀
- 快照与 Git 解耦：本地快照优先于 Git，对未启用 Git 的工程也能提供版本保护；启用 Git 后快照可作为"暂存草稿"

## 关键点
- 快照粒度：自动快照以命令栈合并步为单位（每 50 步或 10 分钟），手动快照即时
- 存储去重：基于内容哈希（SHA256）的块级去重，未变化的对象不重复存储；万级对象快照目录可控制在 MB 级
- 快照元数据：`{id, timestamp, author, description, parent_id, command_count}`，形成 DAG（不只是线性历史）
- 恢复操作：本质是新建当前状态的快照 + 切换到目标快照内容，保持可逆性
- 与 [[05-工程与文件系统]] 的"本地历史 / 文件恢复"是同一系统的不同视图

## 输入 / 输出
- **入**：当前工程状态（[[05-工程与文件系统]] 模型）+ 用户触发的快照命令
- **出**：本地快照库（`.snapshots/` 目录 + index）+ 时间线 UI 数据 + 恢复操作

## 依赖

- **下游**：[[17-02]]（Git 提交前可调用快照）、[[17-03]]（diff 引用快照）
