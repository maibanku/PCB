# 17-05 评论批注评审

> 所属 [[17-协作与版本]]。基于评论与区域批注的异步设计评审，支持 @ 提及、评审流程与离线评审。

## 目标（要实现什么）
- 区域批注：在原理图/PCB 上圈选区域（矩形 / 多边形 / 自由形状），附加评论，关联到坐标与对象引用
- 对象评论：直接对器件/网络/走线/层次块等对象评论，对象变更时评论自动跟随或标记为"失效需复核"
- @ 提及与通知：评论中 @ 队友（基于团队通讯录），通过应用内通知 / 邮件 / 第三方（飞书/Slack/钉钉）推送
- 评审流程：评审状态机（待评审 / 进行中 / 已通过 / 需修改 / 已关闭），评审负责人指派与签署，支持多人会签
- 评论持久化：评论作为工程数据一部分（独立 `comments.edacmt` 文件或嵌入工程包），与 [[17-协作与版本/03-图形化diff]] 图形化 diff / [[17-协作与版本/02-Git集成]] Git 集成（评论可关联到具体 commit）
- 离线评审：评论数据可随 [[17-协作与版本/06-工程包分享]] 工程包导出/导入，支持离线评审后回传合并（类似邮件式评审）

## 关键点
- 评论模型：`{id, target_type, target_ref, author, timestamp, body, status, attachments, parent_id}`；支持线程（回复树）
- 对象引用：使用对象 UID（而非坐标）做关联，避免坐标变化导致评论失联；坐标变化时记录"漂移"
- 通知集成：定义 `INotifier` 接口，可接入应用内/邮件/飞书等；用户可配置接收偏好
- 评审流程参考 industry practice（如 GitHub PR Review、Altium 365 Comment）；状态机可定制
- 与 [[17-协作与版本/03-图形化diff]] diff 集成：评审可绑定到某次 diff 上下文，"在这个 commit 我建议..."

## 输入 / 输出
- **入**：用户批注操作 + 团队成员列表 + 评审配置
- **出**：评论数据（持久化）+ 通知发送 + 评审状态变更
