# 17-04 轻量云同步

> 所属 [[17-协作与版本]]。跨设备的轻量异步同步，**明确不做实时多人协同编辑**。

## 目标（要实现什么）
- 工程云同步：将本地工程（文本格式）同步到云端（自有云 / WebDAV / S3 兼容存储 / 可选 Git remote），跨设备打开与编辑
- 增量同步：基于内容哈希（类似 Git 对象存储），仅同步变化部分，节省带宽与存储
- 冲突检测与合并：检测多端同时修改冲突，提供三方合并工具（复用 [[17-协作与版本/03-图形化diff]] 图形化 diff）；文本工程可自动合并，二进制资源提示手动解决
- 同步策略：可选自动同步（实时/定时）或手动同步（按钮触发），适配不同网络环境与团队习惯
- 离线优先：本地始终保留完整副本，断网时正常编辑，恢复网络后自动同步；冲突本地保留多份待解决
- 不做实时协同编辑：明确不提供多人同时编辑同一工程的实时协作（成本高、收益小），异步同步 + [[17-协作与版本/05-评论批注评审]] 评审为主

## 关键点
- 同步后端抽象：定义 `ICloudSyncProvider` 接口，支持自有云、WebDAV、S3、Git remote 多后端，可插拔（与 [[16-格式兼容/10-适配器插件化]] 适配器思路一致）
- 增量算法：基于内容寻址块存储（CAS），文件分块（如 4KB 块）+ SHA256，仅上传新块；参考 rsync/Git 算法
- 冲突解决流程：检测 → 标记冲突文件 → 提示用户 → 三方合并工具 → 解决后清除标记；自动合并失败时保留两份
- 离线优先设计：所有操作先写本地，同步是后台任务；用户感知不到"在线/离线"差异
- 与 [[17-协作与版本/02-Git集成]] Git 集成协同：Git remote 可作为云同步后端之一，复用 Git 的合并与历史能力

## 输入 / 输出
- **入**：本地工程变更 + 云端配置（后端类型/凭据/同步策略）
- **出**：同步状态（已同步/冲突/失败）、冲突清单、合并工具调用
