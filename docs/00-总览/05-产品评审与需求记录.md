# 05 产品评审与需求记录

> 沉淀产品评审意见为**带编号的需求变更记录**（REQ-001 ~ REQ-023），作为后续规划与开发的决策依据。本文档权威记录评审要点 + 影响面 + **建议决策**；不自动执行架构变更——每条经评审通过后再落到对应 Plan/纲领。
>
> **评审评分**：技术架构 8.5/10 · 完整性 9/10 · 可实现性 5/10 · 商业路径 4/10。
> **优化目标**：可实现性 8/10 · 商业路径 8/10。
> **核心转移**：从"如何造一个 EDA 平台"→"如何最快形成有人用、能生产价值的 EDA 产品"。**核心不是减少技术，而是调整技术出现的顺序。**

## 一、评审核心结论

- ❌ **最大风险——"先造发动机，再造汽车"**：当前自研引擎→渲染→编辑器→原理图→PCB→制造→供应链→AI 的长链路是典型大厂路线；个人/小团队 2 年后可能"拥有漂亮引擎，但用户还画不出一块 PCB"。
- ✅ **建议反转**：用户痛点 → 最小可用 EDA → 获取用户 → 反向补引擎。
- ✅ **数据 > 渲染**：EDA 最难的是数据（Document/Entity/Constraint/Geometry/Command/History），渲染只是显示；当前文档偏重渲染/GUI，应补强核心数据模型。

## 三、详细需求记录

### A. 产品定位与 MVP 范围

#### REQ-001 产品定位分阶段降维
- **评审观点**：第一阶段不要挑战 Altium；改为"面向快速打样和中小企业的轻量化 PCB 设计工具"。
- **现状**：[[00-总览/01-功能设计目录]] A0 定位"竞品级全景套件（对标 KiCad / 嘉立创 / Altium）"。
- **建议变更**：引入**分阶段定位**——MVP 期（0.1~1.0）= 快速打样轻量化；成熟期 = 竞品级全景。两阶段定位并存，文档与对外宣发区分。
- **影响面**：01-功能设计目录 A0、根 README 引言、A2 对标矩阵。
- **建议决策**：✅ 采纳。理由：终态愿景保留（吸引人才/融资），MVP 期对外定位收缩，降低获客与交付难度。

#### REQ-002 目标用户聚焦
- **评审观点**：创客（KiCad 难学）、大学生（软件复杂）、小公司工程师（元件库管理麻烦）、打样客户（设计→生产割裂）。
- **现状**：A0 已列四类用户，但未排优先级。
- **建议变更**：MVP 期聚焦**创客 + 小工程师**（付费意愿与痛点最强）；学生与打样客户作扩展。
- **影响面**：A0 目标用户段。
- **建议决策**：✅ 采纳。

#### REQ-003 MVP 0.1 = PCB 闭环（争议项）
- **评审观点**：只做 导入封装库 → PCB Layout → 简单 DRC → Gerber → 生产；**暂不含原理图**。
- **现状**：MVP（[[00-总览/02-实现路线图]] 第四节）= P1–P8、P11、P13、P14，含完整原理图（P7）。
- **建议变更**：⚠️ **部分采纳**。新增"MVP 0.1 最小切片"= P1 地基 + P3 几何/命令栈 + P6 封装库（仅导入）+ P8a 板框/图层/布局 + P8b 最小布线 + P13 Gerber + 最小 DRC。**保留最小原理图**（器件+导线+网表，砍层次化/复用/PDF）——因原理图→网表→PCB 是 EDA 闭环基础，无原理图的工具只能"抄板"不能"设计"，会限制用户群与 ERC。
- **影响面**：02-实现路线图 新增"产品里程碑"节；P7 标注 MVP 0.1 子集。
- **建议决策**：⚠️ 部分采纳。**待用户拍板**：MVP 0.1 是否含最小原理图？

#### REQ-004 MVP 0.1 暂缓项
- **评审观点**：砍仿真/3D机械/SI-PI/AI/多板。
- **现状**：这些本就在 MVP 之外（Phase 3/5）。
- **建议变更**：✅ 确认暂缓；显式声明 MVP 0.1 不含 P9/P10/P12/P15/P20。
- **建议决策**：✅ 采纳（与现状一致，仅显式化）。

#### REQ-005 核心价值重定位
- **评审观点**：不是"我也有 PCB 编辑器"，而是"画完 PCB 直接生产，不需要懂复杂 EDA 流程"。
- **建议变更**：根 README 与 01 引言的"差异化"从"AI + 供应链"调整为 **"画完即生产的一站式闭环" + AI + 供应链**（闭环前置作为首条）。
- **建议决策**：✅ 采纳。

### B. 架构与核心对象模型

#### REQ-006 架构增 application 层
- **评审观点**：application / editor / eda / engine 四层；EDA 不是游戏。
- **现状**：[[00-总览/03-项目目录结构]] 已有 core/servers/drivers/platform/scene/editor/eda，无 application 层。
- **建议变更**：⚠️ 部分采纳。在 `main/` 之上显式定义 **application 层**（组装编辑器+引擎+服务，处理启动/单文档/多文档/会话），但不大改目录——`main/` 升格为 `application/` 或新增 `app/` 薄层即可。
- **影响面**：03-项目目录结构、P1 plan 的 main/ 定义。
- **建议决策**：⚠️ 部分采纳（轻量引入，避免大改）。

#### REQ-007 强化 EDA Object Model ★
- **评审观点**：EDA 核心 = Document / Entity / Constraint / Geometry / Command / History；Godot 的 Node/Scene/Resource/Rendering 是游戏核心，不完全契合。
- **现状**：P2 核心对象体系对齐 Godot Object/ClassDB/Variant/Signal/Resource/Node；未显式建模 EDA Document/Entity。
- **建议变更**：✅ 采纳。**扩展 P2**（或新增 P2.5）落地 EDA Object Model：`EDADocument`（工程/板/图页的文档根）、`EDAEntity`（所有图元基类，含 UUID+Geometry+Properties+Constraints+History 挂点），与 Object/Node 体系融合（EDAEntity : Object）。
- **影响面**：P2 plan（[[02-核心对象体系/plan/核心对象体系实现计划]]）新增 Task；新建 [[00-总览/07-核心数据模型]]（见 REQ-009）。
- **建议决策**：✅ 采纳（高价值，EDA 真正核心）。

#### REQ-008 PCB 对象树标准化
- **评审观点**：Board → Layer → {Track, Via, Pad, Footprint, Net}；每对象具备 UUID/Geometry/Properties/Constraints/History/Serialization。
- **现状**：P8 PCB 编辑器散落这些对象，未统一基类与六属性契约。
- **建议变更**：✅ 采纳。在 REQ-007 的 `EDAEntity` 基础上，P8 定义 PCB 对象树，每对象实现六属性契约（UUID 稳定主键 / Geometry 几何 / Properties 参数 / Constraints 约束 / History 命令栈集成 / Serialization 文本格式）。
- **影响面**：P8 plan（待起草）、P5 工程格式（序列化）、P3 命令栈（History）。
- **建议决策**：✅ 采纳。

### H. 目录结构重构（重大决策）

#### REQ-023 目录结构重构为 10 个产品视角
- **评审观点**：新目录 00-产品规划 / 01-核心数据模型 / 02-工程文件系统 / 03-图形引擎 / 04-编辑器框架 / 05-PCB核心 / 06-原理图 / 07-制造输出 / 08-供应链 / 09-高级分析 / 10-AI辅助。

- **建议变更**：❌ **建议暂缓激进重构**。理由：
  1. 22 域是**技术蓝图（What）**，编号稳定；重构牵动全部 wiki 链接、frontmatter `plan` 字段、术语表、5 份 plan 的目录引用——成本极高、收益是"换名字"。
  2. 评审的 10 目录是**产品视角（按用户路径）**，与技术域是**两个正交维度**，不必替换。
- **替代方案（推荐）**：保留 22 域技术编号 + **新增产品视角覆盖层**——在 02-实现路线图 加"产品里程碑 MVP 0.1/0.2/1.0"节，每个里程碑引用 22 域的子集（如 MVP 0.1 = P1+P3+P6子集+P8a+P8b最小+P13最小）。技术域（稳定命名）与产品阶段（时间节奏）分离。
- **若坚持重构**：作为 v2 大版本迁移，单独排期，自动化脚本批量改链接。
- **建议决策**：❌ 暂缓（采纳替代方案）。

## 七、评审原文存档（溯源）

> 以下为评审原文要点摘录（用于决策溯源，详见评审输入）：
>
> - **总体**：方向技术价值非常高，目标接近 Altium/Allegro/KiCad/嘉立创专业版；但当前需求最大问题是"先造发动机，再造汽车"。
> - **定位**：第一阶段不要挑战 Altium；改"面向快速打样和中小企业的轻量化 PCB 设计工具"。
> - **MVP**：只做 PCB 快速设计闭环（导入封装→Layout→DRC→Gerber→生产）；暂删仿真/3D/SI-PI/AI/多板。
> - **架构**：增 application 层；EDA 核心 = Document/Entity/Constraint/Geometry/Command/History（非 Godot 的 Node/Scene）。
> - **数据**：新增"00-核心模型"（工程文件系统、参数系统类 SolidWorks Feature、约束系统）。
> - **路线图**：Phase 0（1 月，能开 PCB，仅 OpenGL）/ Phase 1（3 月，能画 PCB）/ Phase 2（6 月，小规模商用）/ Phase 3（原理图仿真 AI 供应链）。
> - **AI**：降级；最有价值是 DRC（天线禁铺铜/晶振距离/线宽不足/电路复用），非聊天。
> - **供应链**：反而应提前；BOM+库存+价格 是商业壁垒。
> - **新增**：用户工作流、商业化（账号/云库/订单/支付）。
> - **评分**：技术架构 8.5 · 完整性 9 · 可实现性 5 · 商业路径 4；优化后可实现性 8 · 商业路径 8。
> - **一句话**：核心不是减少技术，而是调整技术出现的顺序。
