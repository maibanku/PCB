# 04 术语表与命名规范

> **权威单一事实源（SSOT）**。全库中文术语、英文源词、代码符号、UI 翻译 key 四者以此为准。写文档、写代码、做翻译前先查本表。**存在分歧时以本表为准**，并据本表回改历史文档。

## 一、四层命名映射（核心原则）

同一概念在四个层面的写法必须一一对应，不得各自演化：

| 层面 | 例子（footprint） | 例子（courtyard） | 规则 |
|------|------|------|------|
| **英文源词（source）** | `footprint` | `courtyard` | 全小写；用作 UI `tr()` 的 source key |
| **代码符号（symbol）** | `Footprint` | `Courtyard` | `PascalCase`；类/类型/枚举值 |
| **文档中文术语（doc）** | 封装 | courtyard（不译，见 §三） | 正文统一用本表译法 |
| **文件名（file）** | `footprint.h` | `courtyard.h` | `snake_case` |

> 新增术语时，**四层同步确定**，并补登本表 §四。

## 二、争议项决定（先读这一节）

### D1. 元件 vs 器件 vs 元器件

- **器件（component / part / device）** = 一个具体的电子零件实例，已绑定（或可绑定）符号 + 封装 + 3D + 参数。**正文主用词**。
- **元件库（component library）** = **专有名词**，特指 [06-元件库](../06-元件库/) 域（库名，历史命名，保留）。库内个体一律称"器件"。
- **元器件** = 废弃用法。已有"元器件库"等表述统一改为"器件库"或"元件库"。
- 英文 `Component` / `Part` / `Device` 在 ECO、网表、代码上下文均按"器件"处理；`Component Class` → 器件类。

> 一句话：**写零件本身用"器件"；叫那个库用"元件库"**。

### D2. courtyard 译不译 → **不译，保留英文**

- IPC-7351 标准词，Altium / KiCad / 嘉立创专业版均直接用 `courtyard`。
- 译"禁布区"会与 `keepout`（禁布区/禁通孔区）混淆；译"器件占用区"冗长。
- **规则**：正文统一写 `courtyard`。首次出现可括注一次 `courtyard（器件占用区）`，之后只用 `courtyard`。代码符号 `Courtyard`。

### D3. Via / Pad 大小写 → **代码 PascalCase，注释首字母大写**

- 代码符号：`Via`、`Pad`、`Padstack`（`PascalCase`）。
- 文档括号注释：统一首字母大写——`过孔（Via）`、`焊盘（Pad）`、`焊盘栈（Padstack）`。不得写成 `via` / `pad` / `pad stack` / `Pad/Via Stack`。
- 复合：`盲埋孔（Blind/Buried Via）`、`背钻（Back Drill）`、`热焊盘（Thermal Relief）`、`孤立焊盘（Isolated Pad）`。

### D4. 品牌名写法

| 写法 | 指代 | 用法 |
|------|------|------|
| **嘉立创** | 公司（深圳市嘉立创科技） | 指公司、工厂、整体生态 |
| **立创EDA** | EDA 产品（无空格，官方现名） | 指该 EDA 工具；旧称"嘉立创EDA"一律改此 |
| **立创商城（LCSC）** | 元器件商城 | 指供应商/采购 |
| **JLCPCB** | PCB 制造品牌（国际） | 指打样/SMT 下单品牌 |
| **华秋** | 公司/供应商 | 指"华秋 DFM""华秋商城"等 |

> 禁止写法：`嘉立创EDA`、`立创 EDA`（带空格）、`立创eda`。已存在的不一致写法按本表回改。

## 三、固有名词清单（不翻译）

以下词在 UI、文档、翻译资源中**保留英文原形**，不译为中文，也不并入 `tr()` source 池外的中文译法：

- **标准与格式**：IPC-2581、IPC-7351、ODB++、Gerber、Excellon、RS-274X、STEP、IGES、OBJ、VRML、DXF、DWG、SPICE、IBIS、WCAG
- **EDA 专有词**：courtyard、Annotate、Pick & Place、netlist、padstack、solder paste、silk on pad
- **缩写**（直接用，不展开）：BOM、DRC、ERC、DFM、DFA、DFT、DFX、SI、PI、IR Drop、SMD、NSMD、BGA、QFP、QFN、SOIC、TSSOP、SOT、DFN、MSOP、LQFP、TQFP、DC、AC、FFT、MCU、FPGA、SoC、PCB、PCBA、FCT、ICT
- **工具/平台**：Git、ngspice、Godot（架构借鉴对象）、GLFW、Vulkan、OpenGL、CMake

> 带中文惯用译法且本表已登记的（如 DRC 在正文首次可写"设计规则检查（DRC）"，之后用 DRC），以本表 §四"中文惯用"列为准。

## 五、维护规则

1. **新增术语**：在 §四 登记四层映射（英文 / 中文 / 代码符号 / 备注）；争议项进 §二。
2. **写文档时**：正文中文术语查 §四；英文缩写查 §三 是否属固有名词。
3. **写代码时**：类型/枚举用 §四"代码符号"列的 `PascalCase`；`tr()` source 用"英文 source"列全小写形式。
4. **做翻译时**：`tr()` key = §四"英文 source"；译法取 §四"中文术语"；固有名词（§三）原样保留。
5. **回改历史**：发现与本表不一致的旧写法（如"元器件""嘉立创EDA""Pad/Via Stack""Copper Pour / Dynamic Pour 并存"），按本表回改，并在提交信息注明"对齐术语表"。
6. **本表演进**：决策变更先改本表，再批量回改文档；不得在文档里就地偏离。

## 六、待定（需后续决策）

- `pad` 与 `pin` 在"引脚焊盘"语境的边界（当前：pin=引脚/逻辑，pad=焊盘/物理）。
- `device` 与 `component` 代码层是否合并为一个类（当前倾向 `Device` 表一体化绑定，`Component` 表 ECO/网表层的器件实例）。
- `supply chain` 相关术语（MPN / LSC / NRND / EOL）的中文化粒度，进入 P21 时补登。
