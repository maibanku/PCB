> **一句话定位**：面向中小规模电路（~万 Pin 级）的**原生桌面**国产 EDA，主打 **"画图 → 验证 → 输出可直接生产文件"一站式闭环**，并以 **AI 辅助设计** 与 **供应链直连** 作为差异化。

## A. 总览与架构

### A0 产品定位与目标用户
- **定位**：原生桌面 EDA，覆盖"建库 → 原理 → 仿真 → PCB → 验证 → 输出 → 下单"全链路；目标中小电路（~万 Pin），强调开箱即造。
- **目标用户**：
  - 电子工程师（中小板、快速迭代）
  - 创客 / 硬件创业团队（成本敏感、要快）
  - 教育 / 学生（零门槛、可教学）
  - 企业研发（私有库 + 轻协作 + IP 可控）
- **设计哲学**：
  1. **可生产性优先**——任一节点的产出都要为"最终能造出来"服务。
  2. **格式开放不锁定**——能进能出，主流格式全兼容。
  3. **AI 增强而非替代**——所有 AI 建议可接受/拒绝/撤销，不破坏工程确定性。

### A1 端到端可生产主线工作流 ★核心目标
> 这是整份设计的灵魂主线：从"画图"到"可直接生产"的闭环。每个节点标注**产出什么制造数据**。

| # | 节点 | 产出（可生产数据） |
|---|---|---|
| 1 | 建库 / 选型 | 标准器件库（封装 + 3D + 参数 + SPICE 模型 + 供应链信息） |
| 2 | 原理图绘制 | 网表、BOM 雏形 |
| 3 | 仿真验证 | 功能可行性确认（降低改板风险） |
| 4 | PCB 布局布线 | 物理版图、阻抗 / 约束数据 |
| 5 | DRC / DFM / DFT 校验 | 可制造 / 可装配 / 可测试的合规确认 |
| 6 | 制造输出 | Gerber、钻孔、坐标、钢网、IPC-2581 / ODB++、装配图、BOM |
| 7 | 供应链下单 | 直达工厂的生产订单（PCB 打样 + SMT 贴片 + 物料配齐） |

- **贯通性**：节点 1→7 数据贯通；任一节点变更通过 **ECO（工程变更订单）** 向上下游同步。
- **终态**：一次性产出"开箱即造"完整生产包，零手工二次加工。

### A2 对标差异矩阵

| 维度 | 本品 | KiCad | 嘉立创 EDA | Altium |
|---|---|---|---|---|
| 形态 | 原生桌面 | 桌面 | Web + 客户端 | 桌面 |
| 可生产闭环 | 一站式（含下单） | 需外接 | 一站式（自有生态） | 需外接 |
| AI 辅助 | 原生深度 | 无 | 弱 | 有限 |
| 格式兼容 | 全主流进出 | 自有（开源） | 自有 | 自有 |
| 供应链 | 多供应商直连 | 无 | 嘉立创自有 | 弱 |
| 价格 | 待定（可免费+增值） | 免费 | 免费 / 订阅 | 高（商业） |
| 开源 | 待定 | 完全开源 | 闭源 | 闭源 |

### A3 分层架构与原生桌面路线权衡
- **分层架构**：
  ```
  ┌─ UI 层（窗口/面板/快捷键/主题）
  ├─ 编辑器层（原理图 / PCB / 库 / 仿真 / 3D）
  ├─ 核心引擎层（几何 · 数据模型 · 命令栈 · 规则）
  ├─ 平台层（OS 抽象 · GPU 渲染 · 文件 · 网络）
  └─ 服务层（AI · 供应链 · 协作 · 格式兼容）
  ```
- **桌面路线权衡（诚实写）**：
  - ✅ **优势**：大数据量性能、离线可用、原生交互流畅、私有库/IP 可控、不依赖浏览器。
  - ⚠️ **代价**：实时多人协作弱（需自建同步层）、分发与更新成本、跨端即开即用性不如 Web。
  - 🛡️ **缓解**：协作走"工程包 + Git + 轻量云同步 + 评审"组合，**不做**高成本实时协同编辑；性能靠 **自研 C++ 引擎 + GPU 渲染（借鉴 Godot RenderingDevice / CanvasItem）**，对标嘉立创 WebGPU 的万焊盘能力。

## B. 平台与核心引擎

### B1 平台基础
- **跨平台框架**：Windows / macOS / Linux（**自研平台层，借鉴 Godot `OS` / `DisplayServer` 抽象，不依赖 Qt6 / Tauri**）
- **窗口/菜单/工具栏**：可停靠面板、可保存���局、多显示器
- **快捷键体系**��全局可配置映射；预设 **KiCad / Altium / 嘉立创** 键位，降低迁移成本
- **主题**：明 / 暗 / 自定义，图标包可换
- **配置管理**：用户级 + 工程级，分层覆盖
- **国际化 i18n**：中英为主，可扩展多语言
- **自动更新**：版本通道（稳定 / 测试 / 夜间）
- **日志 / 崩溃上报 / 遥测**：遥测可关，崩溃可本地保存
- **无障碍**：键盘全操作、高对比度、界面缩放
> **对标差异**：KiCad 用 wxWidgets，嘉立创用 Web 技术栈；本品**自研引擎（借鉴 Godot 架构）**，原生性能 + 完全可控 + UI 高度一致。

### B2 几何与图元引擎（性能核心）
- **2D 几何内核**：点 / 线 / 圆弧 / 多边形 / 路径
- **布尔运算**（并 / 差 / 交）—— 铺铜、板框、区域计算必需
- **多边形偏移 offset**—— 间距、铺铜收缩、courtyard
- **空间索引**（网格 / 四叉树 / R-tree）—— 万级图元的 DRC 碰撞检测
- **坐标系与单位**：mil / mm / 英寸，原点、相对 / 绝对切换
- **网格与吸附**：栅格、器件中心、焊盘、导线端点
- **增量渲染 / 脏区刷新**：局部重绘（大数据量流畅的关键）
- **GPU 加速**：自研 GPU 抽象（Vulkan 优先 + OpenGL/Metal 后端，借鉴 Godot `RenderingDevice`），2D 图元 `CanvasItem` 式批渲染；脏区增量刷新、LOD、GPU 拾取；对标嘉立创 WebGPU 万焊盘
> **关键设计**：引擎层用 C++20 实现（参考 Godot 源码研究），渲染/GUI/核心自研且与业务解耦；图元以"原子操作"入命令栈，保证可撤销。

### B3 数据模型、命令栈与变更管理（ECO）
- **图元数据结构**：层级化、可序列化、版本化 schema（向后兼容）
- **命令栈 / Undo/Redo**：事务化（多步合并）、内存上限、命名操作
- **选择系统**：单选 / 框选 / 过滤 / 按属性选
- **★ ECO 工程变更订单**（原理图 ↔ PCB 双向同步）：
  - 原理图变更 → 检测差异 → 生成 ECO 列表 → 选择性应用到 PCB（对标嘉立创"更新原理图到 PCB"）
  - PCB 变更（如改封装 / 位号）→ 反向同步回原理图
  - 变更预览 / 选择性应用 / 变更日志 / 可回滚
- **审计**：工程变更可追溯（谁、何时、改了什么）
> **对标差异**：KiCad 用同步机制，Altium 有成熟 ECO；本品把 ECO 做成**显式、可审查、可回滚**的一等公民。

### B4 工程与文件系统 + 多板 / 系统级
- **工程树**：工程 > 板子 > 图页（原理图页 / PCB），对标嘉立创紧凑结构
- **文件格式**：自有**开放文本格式**（JSON/TOML，便于 Git diff）+ 二进制资源（3D / 图）
- **版本快照**：本地历史、文件恢复
- **工程模板**：常用板型、规则预设、叠层预设
- **★ 多板 / 系统级设计**：一个系统含多块 PCB + 连接器 / 线缆关系，**板间信号连通性检查**
- **附件管理**：设计说明、datasheet 链接、参考资料
- **工程打包 / 归档**：含所有依赖库，可离线移交工厂或同事
> **对标差异**：KiCad 工程较松散，嘉立创工程树紧凑；本品 = 紧凑工程树 + **Git 友好的文本格式** + 多板系统级。

## C. 设计编辑器群

### C1 元件库体系
- **符号库编辑器**：图形 / 引脚 / 属性 / Pin 映射
- **封装库编辑器**：焊盘（SMD / 通孔）、丝印、阻焊、courtyard、3D 关联
- **3D 模型库**：导入 STEP / OBJ / wrl，关联封装，原点 / 旋转校准
- **器件一体化绑定**：一个器件 = 符号 + 封装 + 3D + 参数 + SPICE 模型 + **供应链信息**
- **库层级**：本地库 / 在线云端库 / 企业私有库（多级同步）
- **库向导**：批量引脚符号生成、**IPC-7351 标准封装生成器**
- **库搜索**：参数化检索、模糊匹配、供应商料号直达
- **库版本管理 + 依赖锁定**：工程绑定特定库版本，保证可复现
> **对标差异**：KiCad 符号/封装分离，嘉立创器件一体化；本品走器件一体化 + **供应链信息预置**（为 E2 铺路）。

### C2 原理图编辑器
- **图元**：器件、导线、网络标号、总线、电源端口、层次块、子图、端口、注释、图片
- **绘制与放置**：栅格吸附、自动连线、正交 / 任意角度
- **层次化设计**：层次块、子图、总线入口、跨页网络
- **网络表生成**：内部网表 + 通用格式导出
- **ERC 电气规则**：未连接、冲突、电源地、重复位号、悬空引脚
- **位号标注 / 重排**：自动编号 Annotate
- **器件标准化**：原理图符号统一规范（对标嘉立创）
- **复用模块**：带端口的原理图模块，可含 PCB 同步复用
- **BOM 雏形**：属性聚合，直供 D4 / E2
- **输出**：原理图 PDF / 图片
> **对标差异**：覆盖 KiCad Eeschema + 嘉立创；差异化 = AI 辅助选型 / 连线（E1）+ 供应链属性直显。

### C3 PCB 编辑器
- **板框设计**：矩形 / 圆形 / 异形 / 导入 DXF/DWG、开槽、定位孔
- **图层体系**：信号 / 电源地 / 阻焊 / 丝印 / 钻孔 / 用户层；**叠层管理器 + 阻抗计算**
- **设计规则**：间距 / 线宽 / 过孔规则集，按**网络 / 网络类**分级约束（约束管理器）
- **放置**：器件、焊盘、过孔（通孔 / 盲埋孔）、走线、铺铜、丝印、尺寸标注、测试点
- **布局**：移动 / 旋转 / 对齐 / 分布 / 组合 / 锁定、推挤、物理碰撞检查
- **布线**：
  - 单路交互式布线（推挤 / 绕障）
  - 差分对（等长、耦合）
  - 总线 / 多线
  - 蛇形等长（长度匹配）
  - **自动布线**（内置 + AI 增强，见 E1）
  - 拆线 / 重布
- **铺铜**：动态铺铜、热焊盘 / 直连、避让规则、一键重建
- **盲埋孔 / 背钻、阻抗控制走线**
- **DRC**（实时 + 全板）、长度 / 延迟显示
- **3D 实时预览**切换
> **对标差异**：覆盖 Pcbnew + 嘉立创；差异化 = AI 自动布局布线（E1）+ SI/PI 联动分析（D3）。

### C4 仿真
- **SPICE 引擎集成**：ngspice（开源成熟）
- **仿真模型库**：与器件库关联的 SPICE 模型
- **分析类型**：DC 工作点、AC 扫频、DC 扫描、瞬态、噪声、蒙特卡洛 / 最坏情况、参数扫描
- **波形查看器**：多迹、游标、测量、数学运算、FFT
- **原理图联动**：激励源、探针节点
- **模型导入**：第三方 SPICE 模型
> **对标差异**：对标 KiCad ngspice 集成；差异化 = AI 辅助设置仿真、异常波形解读（E1）。

### C5 3D 与机械协同
- **3D 查看器**：实时渲染、剖面、测量、爆炸图
- **3D 导入导出**：STEP / IGES / OBJ / VRML
- **装配干涉检查**：器件-器件、器件-外壳
- **机械 CAD 协同**：导入外壳 / 结构件 Step，板框对位
- **高度限制区**：器件高度 vs 外壳空间
- **渲染输出**：高清图、3D PDF
> **对标差异**：对标 KiCad 3D 查看器；差异化 = 与机械 CAD 双向协同更顺。

## D. 验证、分析与制造输出

### D1 统一校验框架
- **统一检查中心**：ERC（原理图）+ DRC（PCB）+ **一致性检查**（原理图 vs PCB）
- **★ 自定义规则语言**：类约束表达式 / 脚本化规则（对标 KiCad 规则系统）
- **电气网络分析**：连通性、悬空、短路、电源地完整性
- **结果面板**：分级、定位跳转、忽略 / 批准、批量修复建议
- **规则集预设**：按工厂能力 / 板型，可分享 / 云同步
> **对标差异**：KiCad 规则系统强大；本品差异化 = AI 审查建议（E1）+ 规则云同步。

### D2 DFX 体系 ★（补强重点）
- **DFM 可制造性**：最小线宽 / 间距、阻焊桥、丝印上焊盘、孤立焊盘、拼板工艺
- **DFA 可装配性**：器件间距、极性方向、器件重量、波峰焊 / 回流适配
- **★ DFT 可测试性**：测试点覆盖率、可达性、ICT / FCT 夹具适配、探针可达性分析
- **DFX 报告 + 改进建议**
> **对标差异**：Altium 在 DFX 较强；本品 **DFT 可测试性** 是相对 KiCad/嘉立创的补强。

### D3 SI / PI 信号与电源完整性分析 ★（新增，高速必备）
- **SI 信号完整性**：阻抗分析、串扰预估、反射、过孔 stub、眼图（需 IBIS/模型）
- **PI 电源完整性**：电源平面完整性、去耦电容优化、IR Drop 压降、目标阻抗
- 与叠层 / 规则联动
- 报告 + 优化建议
> **对标差异**：Cadence/Altium 高端；本品做"够用级"高速分析，面向中小板高速场景（USB/DDR/高速串行）。

### D4 制造与装配输出 ★（强化）
- **Gerber（RS-274X）+ 钻孔（Excellon）+ 坐标文件（Pick&Place）**
- **钢网 Gerber**（SMT 用）
- **IPC-2581 / ODB++**（智能制造数据包，一站式工厂直收）
- **BOM**（CSV / Excel / 可配齐，含供应链属性）
- **装配图 / 制造图 / 钻孔图 PDF**
- **DXF**（机械图）
- **3D STEP**（整机 / 单板）
- **★ 拼板面板化**：V-cut、邮票孔、工艺边、阴阳板、桥连、自动排列
- **输出模板 + 批处理一键全出**
- **制造前检查**（DFM 前置，避免到了工厂才被打回）
> **对标差异**：覆盖 KiCad + 嘉立创；差异化 = **拼板 + IPC-2581/ODB++ 一键产出"开箱即造"包**，直连供应链下单。

## E. 差异化重点模块 ★

### E1 AI 辅助设计
- **AI 选型助手**：按功能需求推荐器件（结合库存 / 价格 / 生命周期）
- **原理图辅助**：智能连线建议、典型电路模板推荐、缺漏检测（缺去耦 / 上拉 / 续流）
- **自动布局**：基于约束 / 热 / 信号的智能布局（学习优秀设计）
- **自动布线增强**：AI 辅助差分 / 等长 / 绕障
- **★ AI 设计审查**：自然语言 DRC/DFM/可靠性建议（"这条电源走线够宽吗？""去耦够吗？"）
- **对话式助手**：问答、教学、排错（基于当前电路上下文）
- **原理图理解 / 生成**：从文字描述 / 网表生成原理图框架（实验性）
- **模型策略**：本地小模型 + 云端大模型混合；**隐私敏感电路走本地**
> **关键设计**：AI 作为 Copilot，所有建议**可接受 / 拒绝 / 撤销**，不破坏工程确定性与可复现性。

### E2 供应链集成 ★（强化）
- **BOM 配齐**：一键比对多供应商库存 / 价格 / 交期
- **替代料推荐**：Pin 兼容 / 参数近似，含生命周期状态
- **★ 元件生命周期管理**：EOL / 停产预警、NRND 状态、生命周期曲线
- **一站式下单**：PCB 打样 + SMT 贴片 + 物料代购，多供应商比价
- **订单进度跟踪**：设计内查看生产状态
- **合规管理**：RoHS / REACH / 无铅 / 冲突矿物声明
- **供应商对接**：嘉立创 / 华秋 / 立创商城 / Mouser / DigiKey 等（可配置接口）
> **关键设计**：供应链信息在**设计阶段就可见**（成本 / 可造性前置），而非设计完才发现买不到料——这是相对 KiCad 的核心差异化。

## 附录三：技术架构与选型（借鉴 Godot 自研引擎）

> **核心决策**：不使用 Qt6 / Tauri，也不直接依赖 Godot 运行时；**研究 Godot 开源实现，借鉴其架构思想，完全自研 EDA 引擎**。

**语言**：**C++20（已定）**——贴近 Godot 源码便于研究借鉴；几何/渲染开源库生态成熟（Clipper2、earcut、ngspice）；性能与人才储备好。**不采用 Rust**（性能与 C++ 同级，但 C++ 在 Godot 研究与 EDA 库生态上更契合）。

**自研引擎分层（与 Godot 架构映射）**：

| 自研层 | 职责 | 借鉴 Godot |
|---|---|---|
| 平台抽象层 | Win/Mac/Linux OS、窗口、输入、文件、线程 | `OS` / `DisplayServer` |
| 渲染层 | GPU 抽象 + 2D 矢量渲染管线 | `RenderingDevice`(Vulkan/GL/Metal) + `CanvasItem` |
| GUI 框架层 | 自绘控件、布局、面板、主题 | `Control` 节点体系、容器布局、主题 |
| 核心/节点层 | 对象模型、节点树、信号、序列化、资源 | `Object` / `Node`、信号、`Resource`、场景序列化 |
| 编辑器层 | 原理图/PCB/库/仿真/3D 编辑器 | Godot 编辑器架构（插件式、Dock、Inspector） |
| 业务核心层 | 几何/DRC/ECO/格式/SPICE（EDA 专有） | 自研（Godot 无对应物） |

**关键技术借鉴点**：
1. **渲染**：自研 GPU 抽象（Vulkan 优先 + GL/Metal 后端），2D 图元经 `CanvasItem` 式批渲染；脏区增量刷新、LOD、GPU 拾取（picking）。
2. **GUI**：`Control` 式节点树构建 UI，**自绘、不依赖系统控件**，锚点/容器布局、可停靠 Dock、属性 Inspector、命令面板。
3. **对象模型**：节点 + 信号 + Resource；**图元即节点；工程树即场景树**。
4. **脚本/扩展**：自研轻量脚本（类 `GDScript` 思路）或嵌入 Python；C++ 插件接口（类 `GDExtension`）。
5. **编辑器框架**：插件式、工具/模式切换、撤销栈、属性面板——直接借鉴 Godot 编辑器组织方式（Godot 编辑器自身就是"用自己引擎做的专业编辑器"的先例）。
6. **3D**：与渲染层共用 GPU 抽象，用于器件 3D 预览与装配干涉检查。

**可复用第三方库（非框架）**：几何 Clipper2 / earcut、仿真 ngspice、3D 导入 Assimp、字体 HarfBuzz / FreeType、图片 stb / lodepng、JSON RapidJSON、Python 嵌入 CPython。

**为什么不用 Qt6 / Tauri**：
- Qt6 —— 重、许可证争议（LGPL / 商业）、UI 风格统一难、控件体系与高性能自绘矢量编辑器契合度一般。
- Tauri —— 渲染走 WebGPU 可用（嘉立创专业版 10 万焊盘为证），但 **IPC 数据边界、跨平台 WebView 不一致（尤其 Linux WebKitGTK）、重计算上限与交互延迟**是固有瓶颈，性能天花板低于原生。
- 自研（借鉴 Godot）= **最高性能 + 最一致体验 + 完全可控 + 无许可证负担**，契合"全景套件 + 原生桌面"定位。

**备选路线评估（决策记录，2026-07-27）**：
- **Tauri + Web 前端**：开发快、未来 Web 化近乎免费，但性能天花板受 WebView+IPC 限制——为换性能上限而放弃。
- **Tauri + C++ 后端(FFI)**：能复用 C++ 库，但多一层边界、三层数据传递、性能天花板同 Tauri+Rust——放弃。
- **Web 化**："桌面优先 + 后续 Web"是总工作量最大的组合；定为**桌面优先**，不自研 Web 版，未来如需以 WASM 导出降级查看器。
- **Rust vs C++**：性能同级，C++ 贴近 Godot 源码、EDA 库生态更成熟——选 **C++20**。
- **结论**：纯 C++20 自研引擎，桌面优先，赌性能上限与完全可控。

**落地节奏（降低自研风险）**：
1. 先搭建平台抽象 + GPU 渲染 + 输入 → 跑通一个最小 2D 画布
2. 在其上验证自研 GUI（Control 式）→ 做出第一个"原理图查看器"原型
3. 再叠加几何引擎 / 命令栈 / DRC / 文件格式 → 形成可编辑闭环
4. 最后扩展到 PCB / 仿真 / 3D / AI / 供应链

## 附录四：风险与权衡
| 风险 | 说明 | 缓解 |
|---|---|---|
