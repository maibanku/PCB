# EDA 项目目录结构规划

> 代码仓库 `项目资料/pcb/eda-engine/` 的**全局目录权威**。所有 Plan 实现时对照本文件落码，避免边写边挪。命名/构建约定继承自 P1 plan（对齐 Godot：头源同目录、`.h/.cpp`、`snake_case` 文件、`PascalCase` 类型、`eda::` 命名空间、include 从仓库根解析）。

## 一、设计原则

1. **引擎层 vs 业务层分离**：`core/ servers/ drivers/ platform/ scene/ editor/` 是**通用引擎底座**（借鉴 Godot，理论上独立于 EDA）；`eda/` 是 **EDA 专有业务**（Godot 无对应物）。一眼分清"学 Godot 的底座"和"我们要写的 EDA 核心"。
2. **`eda/`（业务核心）vs `modules/`（真插件）**：`eda/` 下是**必需**的业务（原理图/PCB 不是可选的）；`modules/` 是**可插拔扩展**（第三方插件、用户自定义，F2）。区分"核心"与"扩展"。
3. **`editor/`（通用框架）vs `eda/<domain>/`（业务专属）**：`editor/` 放所有编辑器共用的基础设施（dock/inspector/命令面板/工具模式）；各 EDA 编辑器的业务逻辑与专属 UI 放 `eda/schematic/`、`eda/pcb/` 等。
4. **一个 `eda/` 子目录 = 一个功能域 = 一个或多个 Plan**，自包含（头源同目录、自带 `CMakeLists.txt`），便于独立开发、独立测试、未来可整体抽成 `module`。
5. **P1 已定目录不变**：本规划是 P1 目录的**向前扩展**，不改动已定的 `core/math`、`servers/`、`drivers/` 等命名。

## 五、命名与构建约定（继承 P1，全局适用）

- **头源同目录**：`eda/geometry/boolean.h` + `eda/geometry/boolean.cpp`
- **include 从仓库根**：`#include "eda/geometry/boolean.h"`、`#include "servers/rendering_server.h"`
- **每个业务子目录自带 `CMakeLists.txt`**，产出独立库 target（如 `eda_geometry`、`eda_pcb`），依赖关系显式声明
- **target 命名**：`<层>_<模块>`，如 `eda_core`、`eda_servers`、`eda_geometry`、`eda_pcb`、`eda_main`(exe)
- **测试**：集中 `tests/test_<模块>.cpp`（如 `tests/test_geometry.cpp`、`tests/test_pcb_drc.cpp`），链接对应库
- **第三方**：`third_party/` 由 FetchContent 管理，不入 git

## 六、目录建立节奏（随 Plan 逐步建，不一次性铺空目录）

仓库在 P1 Task 1 创建。**每个 Plan 只新建自己用到的目录**，避免大量空目录污染。节奏：

| Plan | 新增目录 |
|------|---------|
| P1 | `core/{math,input}` `servers/` `drivers/{opengl,vulkan}` `platform/glfw` `scene/2d` `main/` `tests/` |
| P2 | `core/{object,variant,os}` `scene/main/` |
| P3 | `eda/{geometry,command}` |
| P4 | `scene/gui/` `editor/{dock,inspector,command_palette,tools,undo}` |
| P5 | `core/io/` `eda/project/` |
| P6 | `eda/library/` |
| P7 | `eda/schematic/` |
| P8 | `eda/pcb/` |
| P9–P15 | `eda/{simulation,mechanical,validation,si_pi,manufacturing}` 等 |
| P16+ | `eda/{formats,collaboration}` `modules/` `tools/cli/` |
